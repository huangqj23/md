## 0. 结论先行

1. **两种出片形态并存。**

   |            | 旁白片（现有）   | 剧情片（新增）                                    |
   | ---------- | ---------------- | ------------------------------------------------- |
   | 画幅       | 9:16             | 16:9，可加 2.35:1 黑边                            |
   | 时长       | 60 秒            | 90–180 秒                                         |
   | 声音       | TTS 旁白连续铺满 | 角色台词（视频原声）加音乐，有声占比 20–60%       |
   | 字幕       | 旁白一层         | 章节标签 / 史实注释 / 台词 / 金句卡 / 声明 / 署名 |
   | 镜头时长   | 由配音长度反推   | 写在剧本里                                        |
   | 适合的模板 | 节气、古诗讲解   | 群像、第一人称、纪念人物                          |

2. **剧情片的第一个模板做群像。**
   - 对标账号的头号爆款（668 万赞）就是群像，而且和古诗方向完全契合。
   - 群像以固定侧面远景为主，人脸小，写实人脸被拒收的风险最低。
   - 每个人物只出现 2–4 个镜头，角色的声音不一致时也不明显。
3. **先实测，再写代码。** 剧情片依赖两项我们没验证过的能力：
   - Seedance 原生中文台词：念得对不对、口型和音质怎么样、开音频后 AFP 变不变；
   - 写实人脸能不能过审。
   - 这两项的结果决定剧情片的路由，安排为 Phase 1.6。实测一律用 480p、4–5 秒，约 20 个片段，预算控制在 2.5 万 AFP 以内。
4. **成本。** 一条 2 分钟剧情片（16:9 720p，和 9:16 每秒 AFP 相同）：
   - 全用 Seedance 2.5，连同关键帧和重做约 12 万 AFP，Large 套餐每月只够 2 条；
   - 人物段用 2.0、高潮用 2.5，约 8 万 AFP，每月 3 条。
   - 详见第 6 节。
5. **Phase 2 重排。**
   - 多层字幕、金句卡、叠化转场提前：用 ASS 和 ffmpeg 就能做，不花模型额度。
   - huashu motion 后移。
6. **按现有资源先动起来。**
   - 方舟 Key 到位之前：视频全走 MiniMax H3，关键帧和参考图走中转的 gpt-image-2.5，配音走 MiniMax speech-2.8。
   - H3 总是输出原声，正好用来先验证「保留镜头原声」这条路。
   - 先实测、再写代码、最后出验收片，花额度的两步都要先报预估、你确认后再跑。

## 3. 剧情片的出片规格

### 3.1 画面

- **16:9，720p 生成。** 合成时放大到 1920×1080：`compose.SIZES` 已经有 16:9。
- **项目级 `letterbox: 2.35`。** 合成时把画面裁成 2.35:1 居中，上下补黑边；台词和注释放在下方黑边里，不挡画面。
- **新增两个风格预设：**
  - `film-history`：历史群像、纪念人物；
  - `pov-drama`：第一人称情感片。
  - 两者都新增 `video_prefix` 字段，放「统一前置要求」，写在每个视频提示词的最前面。见第 5 节。

### 3.2 声音

每个镜头新增 `voice` 字段，取值如下：

| 取值        | 含义                         | 视频请求                                     | 合成                   |
| ----------- | ---------------------------- | -------------------------------------------- | ---------------------- |
| `dialogue`  | 镜头里的角色说一句台词       | `generate_audio: true`，台词写进提示词       | 保留镜头原声           |
| `ambient`   | 没有台词，只要环境声         | `generate_audio: true`，提示词写「无人说话」 | 保留镜头原声，压低音量 |
| `narration` | 画外旁白（旁白片的现有做法） | `audio: false`                               | TTS 配音               |
| `none`      | 只有音乐                     | `audio: false`                               | 静音，只铺 BGM         |

- **剧情片的默认值是 `ambient`。**
- **BGM 遇到台词时自动压低。** 现有的 sidechain 压缩改为以「台词和旁白」作为触发信号，环境声不触发。
- **字幕时间。**
  - 第一版：台词字幕从镜头开始后 0.3 秒显示到镜头结束，一镜只有一句台词时够用。
  - 后续：用本地 Whisper 做对齐和校对（Phase 3）。顺带检查模型有没有念错字。
- **替换配音的入口。** 对标账号近期的 3 部片改成了真人配音，所以要支持「原声不理想时换成外部配音」：如果存在 `audio/<镜头>.override.wav`，就用它替换这个镜头的原声。
- **角色声音一致性。** 视频模型每次生成的声音都不同。2026-10-13 你试听的结论：H3 原生声音更贴合人物年纪，用 TTS 做的声音样本反而不合适。所以台词默认不带参考音频，靠提示词里的声音描述（`characters[].voice_desc`）让各镜头的声音接近，见 3.5。

### 3.3 字幕层

新增几种 ASS 样式。所有文字都由合成阶段叠加，不让模型在画面里写字。

| 样式      | 来源字段                       | 位置                       | 显示时间                  |
| --------- | ------------------------------ | -------------------------- | ------------------------- |
| `Label`   | 镜头 `label`（只在变化时显示） | 左上                       | 从这个镜头开始，显示 3 秒 |
| `Caption` | 镜头 `caption`                 | 底部，在台词上方，灰色小字 | 整个镜头                  |
| `Line`    | 镜头 `line`                    | 底部，白色粗体             | 见 3.2                    |
| `Card`    | `kind: "card"` 镜头的 `text`   | 全屏居中，书法字体         | 整个卡片镜头              |
| `Name`    | 项目 `title`                   | 左上，小字加书名号         | 第 5 秒起，显示 3 秒      |
| `Notice`  | 项目 `notice`                  | 右侧竖排，半透明           | 全片                      |
| `Credit`  | 项目 `credits`                 | 片尾左上                   | 最后一个镜头              |
| `AILabel` | 固定（现有）                   | 右上                       | 全片                      |

- **书法字体选 OFL 授权的马善政毛笔楷书（Ma Shan Zheng）。** 由 `fonts.py` 下载和检查，和霞鹜文楷的处理方式一样。
- **剧情片不叠大字封面标题。** `cover_title` 只用于封面图。

### 3.4 镜头时长与转场

- **剧情片的镜头时长写在剧本里**（字段 `seconds`），视频模型按整秒生成，Seedance 最短 4 秒。不再由配音时长反推。
- **每个镜头新增 `transition` 字段**，可选：
  - `cut`：硬切，默认；
  - `dissolve`：叠化 0.6 秒，用 ffmpeg `xfade`；
  - `black`：先黑场 0.5 秒。
  - 历史群像以叠化为主，第一人称情感片以硬切为主。
- **快剪先实测再决定。** 2–3 秒一个镜头的快剪，按 4 秒计费会浪费三成以上额度。Phase 1.6 测一下 Seedance 能不能「单次生成多镜头」，也就是一个 10 秒的片段里切 3–4 个镜头。能的话，快剪段落按「一段多镜头」来写。

### 3.5 生成方式：首帧为主，参考模式为辅

视频模型有两种生成方式，**同一个请求只能用一种**。MiniMax 文档原文：「图生视频与多模态参考生视频互斥」。

|            | 首帧图生视频（默认）                   | 参考模式                                                                      |
| ---------- | -------------------------------------- | ----------------------------------------------------------------------------- |
| 输入       | 一张关键帧，可加尾帧                   | 最多 9 张参考图、3 段参考视频、3 段参考音频（每段 2–15 秒，合计不超过 15 秒） |
| 构图       | 先看关键帧联系表，满意了再花视频的钱   | 模型自己构图，出了视频才看得到                                                |
| 抽卡成本   | 低：重画关键帧按图片计价               | 高：每次重试都按视频计价                                                      |
| 角色一致性 | 靠关键帧；视频后段脸可能走样           | 直接参照角色图，跨镜头更稳                                                    |
| 角色声音   | 不能带参考音频                         | 可以用参考音频固定音色                                                        |
| 运镜和动作 | 受首帧限制，大幅运镜或走进新空间容易崩 | 更自由                                                                        |

- **默认用首帧。** 额度紧，在图片阶段把构图定下来最省钱。
- **两类镜头写 `mode: "ref"`：**
  - 大幅运镜，或人物穿越空间；
  - 多个角色同框互动。
- **台词镜头默认用首帧，不带参考音频。** 2026-10-13 试听：H3 原生声音更贴合人物年纪；用 TTS 音色 `audiobook_male_1` 做的声音样本，音色不合实际人物的年纪。
- **声音靠文字描述拉近。** 每个角色在 `characters[].voice_desc` 里写声音（年龄、音色、语速），流水线把它拼进这个角色台词镜头的提示词。效果在验收片里看。
- **需要严格一致时（可选，没测过）：** 从这个角色最满意的一段 H3 原声里截 2–15 秒做参考音频。代价是只能用参考模式，构图交给模型。
- **参考图不额外花钱。** 用的是角色的全身图和大头照、场景参考图（4.1 的 `scenes`），都是 characters 阶段本来就要生成的。
- **对标作者两种都用。** 《被贬》工作流里他先定首帧；话题标签里「#sekosd 全能模式」出现 9 次，那是 Seko 里 Seedance 的全能参考模式。
- **现状：**
  - 已完成（2026-10-12）：
    - `VideoRequest` 新增 `ref_images` 和 `ref_audio`；
    - Ark 和 MiniMax 共用的 `media_content` 会发送 `reference_image` 和 `reference_audio`；
    - 提交前检查：两种模式不能混用、数量和时长不超限、音频只能是 MP3 或 WAV；
    - 可灵明确拒收参考模式。
  - Phase 2 做：剧本的 `mode` 字段、视频阶段按 `mode` 组装请求、把角色的 `voice_desc` 拼进台词提示词。
  - 待核实：Seedance 是否同样互斥、角色名是否相同。方舟的文档页是动态渲染的，没抓到内容，拿到 Key 后实测。
- **第三方出图工具（如 Midjourney）不接入。**
  - 对标账号的数据里没有它的痕迹，他用的是 Seko 和即梦，背后是同一批 Seedance、Seedream 模型。
  - Midjourney 没有可用于自动化的官方 API，以接入时的官方说明为准；用非官方方式调用违反它的服务条款。
  - 想要它的画面，可以手工出图，存成 `data/projects/<项目>/keyframes/<镜头id>.png`：
    - 关键帧阶段会跳过已有文件，预估也不再计费；
    - 视频阶段会把任何格式统一转成 JPEG 再上传；
    - 画幅和人物外貌要和剧本一致。
  - 剪映可以作为可选的手工收尾：局部重绘、延长、画质增强。把 `final.mp4` 和 `final.srt` 导进去处理即可。

## 4. 剧本 JSON 的变化

### 4.1 新增字段

项目级：

| 字段        | 说明                                                                                                 |
| ----------- | ---------------------------------------------------------------------------------------------------- |
| `template`  | `narration`（旁白片，默认）或 `drama`（剧情片）。`Project.template` 字段已经存在，导入时还没有读取它 |
| `letterbox` | `2.35` 表示加电影黑边，留空表示不加                                                                  |
| `notice`    | 竖排声明，例如「剧情演绎，无不良导向」「改编自……史料」                                               |
| `credits`   | 片尾署名，字符串数组                                                                                 |
| `scenes`    | 场景参考：`[{"id", "look"}]`，每个场景出一张 16:9 参考图，镜头用 `refs` 引用                         |

镜头级：

| 字段         | 说明                                                                                                                 |
| ------------ | -------------------------------------------------------------------------------------------------------------------- |
| `seconds`    | 剧情片必填，4–15 的整数（2.5 可到 30）                                                                               |
| `voice`      | `dialogue` / `ambient` / `narration` / `none`，见 3.2                                                                |
| `speaker`    | 说台词的角色 id                                                                                                      |
| `line`       | 台词，一句，12 字以内                                                                                                |
| `caption`    | 史实注释，一句，20 字以内                                                                                            |
| `label`      | 章节标签：人物名、人生阶段或「地点 · 事件」                                                                          |
| `transition` | `cut` / `dissolve` / `black`                                                                                         |
| `kind`       | 默认 `clip`；设为 `card` 表示金句卡，这时只需要 `text`、`seconds`，可选 `over`（叠在哪个镜头的画面上；不写就是黑场） |
| `mode`       | 默认 `frame`（首帧图生视频）；`ref` 表示参考模式，用 `refs` 里的角色图、场景图，见 3.5                               |

`narration` 在剧情片里改为可选，只有 `voice: narration` 的镜头才需要写。

角色新增两个字段：

- `voice_desc`：声音的文字描述（年龄、音色、语速），例如「四十七八岁，嗓音低沉略沙哑，说话慢」，拼进这个角色台词镜头的提示词；
- `tts_voice`（可选）：MiniMax 音色 id，只在台词改用 TTS 配时用，要按人物年纪先试听。

```json
      "transition": "dissolve",
      "refs": ["dufu", "qinzhou"],
      "image_prompt": "……",
      "video_prompt": "杜甫牵着瘦马走在陇山道上，风吹衣袍，远景缓慢横移",
      "camera": "横移"
    },
    { "id": "c03", "kind": "card", "text": "露从今夜白，月是故乡明", "seconds": 4, "over": "s06" }
  ]
}
```

### 4.3 校验规则

- **硬错误（拒绝导入）：**
  - 剧情片的镜头没写 `seconds`；
  - `voice: dialogue` 却没有 `line` 或 `speaker`；
  - `speaker` 或 `refs` 指向不存在的角色或场景；
  - `card` 没有 `text`。
- **软提示（只提示）：**
  - 台词超过 12 字，或注释超过 20 字；
  - 估算的有声占比超过 70% 或低于 15%；
  - 第 1 个镜头既没有台词也没有注释（钩子太弱）；
  - 同一角色出现超过 6 个台词镜头（声音一致性风险）。

### 4.4 改动后重做什么

在 v2 第 3.3 节的规则基础上补充：

| 改了什么                                        | 重做什么                                   |
| ----------------------------------------------- | ------------------------------------------ |
| `line`、`speaker`、`voice`、`seconds`           | 只重做视频：台词就在视频原声里             |
| `caption`、`label`、`transition`、卡片的 `text` | 只重新合成，不花额度                       |
| 场景的 `look`                                   | 场景参考图，以及引用这个场景的关键帧和视频 |

## 5. 提示词规则：写进哪里

对标作者公开的方法，不是每条都适合我们。他用的很可能是「多参考图生视频」，场景要靠文字描述；我们是「首帧图生视频」，场景和衣着已经在关键帧里了。所以按落地位置分成三类。

### 5.1 写进风格预设（`presets/styles.yaml`）

全片统一的要求放预设，每个镜头自动追加，比让 Claude 每镜重复写更可靠。

- **反向约束：已完成（2026-10-12）。**
  - 现有 5 个预设的 `video_suffix` 末尾统一加了「全程一个连续镜头，不切换镜头、不插入特写，不新增首帧里没有的人物」。
  - 合成是按镜头切的，一个片段内不能再切。约束写的是「不切换、不插入」，不影响「推近」这种连续运镜。
  - 「人物情绪克制」只加在克制风格上：`guofeng-ink`、`cinematic-guofeng`、`red-epic`。
  - 负面词模型不一定听，Step 1 实测时顺带观察有没有自己切镜头或冒出新人物。
- **统一前置要求：Phase 2 做。**
  - 新增 `video_prefix` 字段，`film-history` 的示例：「固定侧面远景，镜头缓慢横移，真实历史电影实拍质感，自然光，人物在画面中偏小」。
  - 剧情片的提示词拼成 `video_prefix + video_prompt + 台词 + camera + video_suffix`。

### 5.2 写进 skill（`short-video`）

- **已完成：** `storyboard-rules.md` 写明不用重复写反向约束；一个片段就是一个连续镜头，想要多个景别就拆成多个镜头。
- **`video_prompt` 仍然只写一个主要动作**，不重复描述场景和衣着：首帧里已经有了，再写一遍可能和画面冲突。
- **Phase 2 随剧情片一起写：**
  - 台词：一镜一句，口语，12 字以内；写法（`角色名说：「……」` 还是直接写台词）等 Step 1 实测后定；引用的诗句按 `fact-check.md` 逐字核对。
  - 只在情绪高点给特写：眼睛、泪水这类特写一条片只用 1–2 次，单独成镜，并标 `photoreal`。
  - 什么时候写 `mode: "ref"`：大幅运镜、多人同框；其余镜头（包括台词镜头）默认首帧。见 3.5。
  - 每个有台词的角色都要写 `voice_desc`，写清年龄和音色，H3 按它配音。
  - 新增 `references/templates.md`，写清三套模板的节拍：
    - 群像：引子 5% → 每人约 10 秒、三拍 → 名句高潮约 30% → 回到现代；
    - 第一人称：人生阶段 POV，一件信物贯穿，首尾呼应；
    - 纪念人物：按年代推进，史实注释配台词，结尾落在名言或课文上。
  - 选题加一道检查：「有没有集体记忆」。地方传说、冷门人物默认不做。

### 5.3 暂不需要

| 技巧           | 原因                                                                                      | 什么时候再看       |
| -------------- | ----------------------------------------------------------------------------------------- | ------------------ |
| 参考视频管动作 | H3 支持 `reference_video`（最多 3 段、合计 15 秒），但还没有参考视频素材的来源            | Phase 3            |

## 9. 风险与待核实

1. **写实人脸。**
   - 第一人称片和纪念人物片大量用到写实人脸特写，Phase 0 里 Seedance 拒收过写实人脸首帧。
   - 应对：
     - 群像先行，它本来就以远景为主；
     - 人脸镜头走 H3；
     - 或者换成不那么写实的电影风格。
   - 第一人称片放到 Phase 3，等实测结果再定。
   - **2026-10-13 实测：H3 收写实人脸近景**（虚构人物，含泪），视频后段脸不走样。Seedance 仍待核实。
2. **原生台词质量。**
   - 可能出的问题：念错字、多音字读错、同一角色声音前后不一致。
   - **2026-10-13 实测（H3）：** 5 句全部念对，包括一句诗；孩子的台词自动用了孩子的声音。试听结论（2026-10-13）：H3 原生声音更贴合人物年纪，用 TTS 做的声音样本反而不合适。
   - 应对：
     - 台词短，一镜一句；
     - 提示词里写清角色的声音描述（年龄、音色、语速）；
     - 需要严格一致时，再试用这个角色的 H3 原声做参考音频；
     - 实在不行，用替换入口换成外部配音（真人或 TTS）。
3. **开原生音频的计费**还不确定，要在 Phase 1.6 核实。
4. **Agent Plan 的使用边界**（同 v2 第 7 节第 1 条）。片子变长后调用次数增加，仍然坚持在 Claude Code 里由 skill 驱动、有人值守，并发保持 2。
5. **时长和额度。** 2 分钟片接近单日额度，一天只能出一条正式片。草稿先行、只重做出问题的镜头，是控制成本的主要手段。
6. **合规。**
   - 历史题材加「改编自史料」声明；
   - 红色题材不生成领袖和英烈的写实形象（同 v1）；
   - 漫画或小说改编要先拿到授权；
   - AI 标识照旧：画面角标、文件元数据、发布时勾选。
7. **同质化和抄袭争议。** 可以学结构和方法，但不复刻对标账号的具体作品（题材组合加台词）。选题用我们自己的节点和古诗库。
8. **样本偏差。** 结论只来自一个账号。旁白片是否也该改成横屏或台词驱动，要等我们自己的发布数据。
9. **M Plan 周额度。**
   - H3 视频只受周窗口限制，方舟到位前所有视频都压在这一个额度上。
   - Step 1 先用 1 段实测出每秒消耗多少百分比，再排实测和验收片的节奏；周额度用完就等下一个周期（下次刷新 10-16）。
   - **2026-10-12 实测：** 1 段 6 秒 768P 的 H3（`p16_say_quote`），周窗口从 96% 降到 93%。
     - 约每秒 0.5%，一周约 200 秒 H3。百分比只到整数，实际在 170–240 秒之间。
     - Step 1 剩下 13 段约 82 秒，约占 41%；Step 3 验收片约 80 秒加重做，约占 40–50%。两者加起来超过本周剩下的 93%，要么精简实测，要么验收片推到 10-16 刷新以后。
10. **图像中转。**
    - 第三方服务：单价、稳定性和内容审核都不由我们掌控，提示词和参考图会经过它。
    - 2026-10-12 实测：第一次请求返回 HTTP 502「服务过载」，约 45 秒后重试成功；每张图约 38 秒；不按请求的尺寸出图（已在适配器里裁成目标比例）。
    - 应对：
      - 只发虚构人物和公版题材，不上传真人照片；
      - 每次运行都记账；
      - 方舟到位后关键帧改回 Seedream，中转只留作封面和需要写字的画面的备选。
11. **H3 和对标效果的差距。** 对标账号用的是 Seedance。H3 的画质、台词和人物一致性可能达不到同样水平，Step 1 的结论只代表 H3。
