## 0. 结论先行

1. **不要追求"一个 prompt 直接出片"，而是"一个 prompt → 一组可编辑的中间产物 → 确定性合成"。** 可控性靠三样东西：结构化的分镜表（`project.json`）、能单独重做的每个镜头、锁定好的角色/风格库。全自动模式就是"每个检查点都自动通过"，随时可以切回人工审核。
2. **生产顺序：音频先行 → 关键帧（图）→ 图生视频 → 合成。** 先有旁白或歌曲，才能定下每个镜头的时长；先出图再动起来，比直接文生视频可控得多。
3. **主力模型（国内可直接用）：**

| 环节        | 主力                                                                          | 备选 / 补充                                                                 | 说明                                                                       |
| ----------- | ----------------------------------------------------------------------------- | --------------------------------------------------------------------------- | -------------------------------------------------------------------------- |
| 编剧 / 分镜 | 国内旗舰 LLM（DeepSeek / Qwen / Kimi / 豆包，直接复用 ai-daily 的多厂商配置） | Claude / GPT / Gemini                                                       | 用你自己的盲评定主力，见第 6 节 Phase 0                                    |
| 关键帧      | **Seedream 5.0 Pro**（火山方舟）                                              | GPT Image 2（画面里要写字时）、Nano Banana Pro                              | Seedream 人物最真、最便宜，国内直连                                        |
| 视频        | **Seedance 2.0**（多参考图、多镜头、原生音频）                                | **可灵 3.0 / O3 / Turbo**（写实人物）、**MiniMax H3**（性价比高、开源权重） | Gemini Omni 榜单第一，但国内用不了，API 也没开放，先观望                   |
| 旁白        | **豆包语音合成 2.0**（情感预测版）                                            | MiniMax Speech 2.8                                                          | 和 Seedance 同一个火山账号                                                 |
| 歌曲        | **Suno v5.5**（质量最好，但没有官方 API，作为半自动步骤）                     | MiniMax Music 3.0（有 API，状态待确认）、海绵音乐（只有 App）               | 原创生成；"歌曲具象化"类在发布时直接选抖音曲库原曲（限站内）；不做 AI 翻唱 |
| 数字人唱歌  | **可灵数字人 2.0**（单段最长 5 分钟，支持唱歌）                               | OmniHuman 1.5（每段约 35–60 秒）                                            | 副歌部分穿插 B-roll                                                        |
| 合成        | **FFmpeg + ASS 字幕**，另导出剪映草稿供人工精修                               | Manim（物理公式动画）                                                       | 合成一步完全确定，不调用模型                                               |

4. **成本**：60 秒成片大约 **¥40–100**，其中视频生成占七成以上。草稿用 480p/720p 或 mini/Turbo 档，确认后再出 1080p。
5. **四个必须提前处理的风险**：① Seedance 2.0 **拒收写实人脸参考图**，写实"古典美女"要走可灵；② "电视剧高光"撞上**版权和广电总局"AI 魔改"专项治理**，要改成"公版原著桥段的原创演绎"；③ 红军长征题材要**尊重史实，不生成领袖和英烈的写实形象**；④ **AI 生成标识**是强制要求，在流水线里默认加上。

**建议的落地顺序**：T1（古诗/节气）→ T2（美景、特效、长征）→ T3（数字人唱歌）→ T4（群像/剧情）。T1 最容易自动化、风险最低，也最能验证整条管线。

**时间节点**：2026 年 10 月是红军长征胜利 90 周年（1936 年 10 月会宁会师），霜降在 10 月 23 日前后，立冬在 11 月 7 日前后。选题日历应该提前两周把这些节点推给你。

各模板的结构：

- **T1 旁白型（60–90 秒）**：前 3 秒放钩子（最美的一个镜头 + 一句设问）→ 正文 8–14 个镜头，每个 4–6 秒 → 结尾一句金句或互动提问。字幕是核心，用开源的宋体/楷体（思源宋体、霞鹜文楷，均为 OFL 授权，可以商用），每屏只放一句。
- **T2 音乐型（30–60 秒）**：歌曲有两种来源：AI 原创，或者"歌曲具象化"（选一首抖音曲库里的热门歌，按歌词逐句出画面）。检测节拍（librosa）→ 镜头切在重拍上，副歌用最强的奇观镜头。没有旁白，只有歌词字幕。
- **T3 数字人型**：歌曲按乐句切成 10–30 秒的段 → 每段用同一张角色定妆照做对口型 → 主歌全程对口型，副歌插 2–3 秒的 B-roll → 拼接。
- **T4 群像 / 剧情型**：场景卡 + 角色卡（每个角色一张定妆照）→ 用多镜头生成。每个镜头写实面部最好不超过 3 张，人群放在中景和远景，近景只给主角。

- **这些作品用的就是主流模型**：《琵琶行》封面标着"MJ | AIGC"；《梦回盛唐上元夜》的作者说要分享"完整图片提示词"，说明是先出图再图生视频，和本方案的主线一致；《太公在此》的说明里写着"本视频由 Lib…"生成（文字被截断）。

## 2. 系统架构：可控性怎么做

```
 prompt / 选题日历
      │
 ①选题卡 ──► ②剧本（+事实核查）──► ③分镜表 project.json ◄── 角色库 / 风格库（锁定）
      ▲ 人工检查点A               │ 人工检查点B（分镜 + 关键帧联系表）
      │                          ▼
      │      ④音频：旁白 TTS / 歌曲 ──► 得到时长和时间戳
      │                          ▼
      │      ⑤关键帧（Seedream）──► ⑥图生视频（按路由表选 Seedance / 可灵 / H3）
      │                          ▼                      ↘ ⑥'数字人对口型
      │      ⑦质检：视觉模型打分 + OCR 查乱码 + 人脸相似度 → 每镜 best-of-N，不合格重做
      │                          ▼
      └──── ⑧合成：FFmpeg（字幕、转场、混音、AI 标识）＋ 剪映草稿 ──► 人工检查点C ──► 发布
```

关键设计：

- **每个阶段都把产物落盘**：选题卡、`script.md`、`project.json`、图片、视频片段、音频。改哪一步就从哪一步往下重跑，其余的复用缓存。
- **缓存键**：`sha256(厂商, 模型, prompt, 参考图哈希, 参数, seed)`。同样的请求不付第二次钱。
- **每个镜头独立**：状态机为 `draft → generated → approved / rejected`。在联系表里点"重做"只会重跑这一个镜头。
- **预算闸门**：生成前按各家单价估算成本，超出上限就停下来等你确认；每个项目单独记一本账（`ledger.jsonl`）。
- **三档审核**：`--review full`（三个检查点都停）、`light`（只停 B）、`none`（全自动，只靠质检把关）。"我只需要给 prompt"对应的就是 `none`。

## 3. 选题与故事引擎

**三路候选来源：**

| 来源   | 内容                                                                                                                                                                                                                                                                                                           | 实现方式                                                                 |
| ------ | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------ |
| 日历   | 24 节气、传统节日、纪念日（长征、国庆、高考、诺贝尔物理学奖公布等）                                                                                                                                                                                                                                            | 节气用天文算法库计算（如 `sxtwl` / `lunar-python`），纪念日维护一份 YAML |
| 经典库 | 唐诗宋词、诗经楚辞（GitHub 上的 `chinese-poetry` 数据集）；《古文观止》等文言名篇；民俗由来与神话（封神、山海经、门神年画、节俗故事，像"太公在此"这类）；励志金句；公版名画（外国名作用大都会博物馆、荷兰国立博物馆等的 CC0 开放图库，国画逐张确认来源授权）；物理定律清单；长征重要节点（以官方党史资料为准） | 本地入库，按"已做 / 未做"去重                                            |
| 热度   | 抖音热榜、巨量算数、你收藏的爆款                                                                                                                                                                                                                                                                               | v1 由你手工录入（贴链接或填标题）；v2 再考虑半自动采集，注意平台规则     |

**打分**：`时令性 × 0.3 + 热度 × 0.25 + 新颖度 × 0.2 + 可视化潜力 × 0.15 − 风险 × 0.1`。LLM 一次给出 10 个候选，每个附 3 个标题或钩子变体，你挑一个，或者让系统直接取最高分。

**标题公式**（来自你收藏的样片）："系列名 | 诗句"（种田·群像 | 山中何事？松花酿酒）、"风格标签 + 诗句"（中式意境 巨物美学 古道西风瘦马）、对仗金句（龙藏渊薮，风待云生）、"终于有人把这首歌具象化了"。选题时同时确定属于哪个系列。

**各方向的故事生成套路：**

- **古诗**：选诗 → 逐句拆意象（景、人、物、情绪）→ 每句 1–2 个镜头 → 朗诵加一句白话点评。
- **文言文**：原文分段 → 白话译文（LLM 生成，再人工或二次模型校对）→ 原文用朗诵、译文用字幕，或者反过来。
- **节气**：物候三候 + 一首相关古诗 + 一个民俗 + 一个当代生活提醒。
- **物理**：两种模式。讲解型：生活现象当钩子 → 原理 → 公式（Manim 精确绘制）→ 应用。科幻叙事型：选一个反直觉的假说或定律（单电子宇宙、时间膨胀、熵增），用电影画面加旁白讲成一个小故事。两种都要求剧本附出处（教材或维基百科），由第二个模型做事实核查。
- **长征**：选一个真实事件（四渡赤水、飞夺泸定桥、爬雪山过草地等），时间、地点、人数一律以权威史料为准；画面用群像、背影、远景和象征性意象（红旗、雪山、金光），不做领袖特写。
- **群像 / 原著桥段**：从公版名著里挑情节（如《红楼梦》诗社、《兰亭集序》曲水流觞），先写角色卡和场景卡，再写分镜。

### 4.2 关键限制：Seedance 2.0 不收写实人脸

多家平台都确认了这一点：Seedance 2.0 会拒收含写实人脸的参考图或首帧，这是上游的防深伪过滤器（[APIYI](https://docs.apiyi.com/en/faq/seedance2-asset-face-reference)、[Civitai](https://developer.civitai.com/orchestration/recipes/seedance)）。官方给的路径是私有素材库：虚拟形象自动入库，真人需要本人核验（[BytePlus 文档](https://docs.byteplus.com/docs/ModelArk/2315856)）。据一家转售商说，素材库在部分渠道是单独付费的附加服务，需要找官方确认。

对你的方向，影响和应对如下：

- **写实"古典美女"**：关键帧用 Seedream 出图，图生视频**路由给可灵**。
- **国风插画、3D 国漫、水墨风人物**：可以继续用 Seedance，但这类风格是否会被过滤器判定为写实人脸，需要在 Phase 0 实测拒绝率。
- **Seedance 内的一致性**：Civitai 的说明提到，Seedance 自己生成的近期结果可以作为参考再次输入，可以试试"先用文生视频定角色，再用它的输出当参考"。
- 把"被拒绝"当成正常状态来处理：被拒绝时自动降级到可灵并记录原因，不要让整个任务失败。

### 4.3 出效果的 10 条做法

1. **图先行**：Seedream 生成关键帧 → 在联系表里过目 → 图生视频。构图、服饰、色调都在图这一步锁定，视频模型只负责动起来。
2. **音频先行**：旁白合成后拿到每句的时长，镜头时长 = 句长 + 0.3–0.5 秒。Seedance 支持 4–15 秒的整数时长，向上取整后再裁剪。
3. **角色库**：每个角色先出一套定妆照（正面、侧面、全身），之后每个镜头都带上同一组参考图（Seedream 多图参考、Seedance `@image`、可灵主体参考）。
4. **风格库**：每种风格是一份固定后缀（画风、色板、镜头、光线）加负面词，比如 `guofeng-ink`、`epic-myth`、`red-epic-golden`、`physics-clean`。分镜阶段只写内容，风格由系统自动拼接。金箔画、工笔、敦煌壁画这类**材质风格**，单靠文字出不来，每个预设还要带 1–3 张风格参考图（出关键帧时作为参考图传入）；视频生成后，材质容易变淡，合成时再叠一层宣纸或金箔纹理（FFmpeg `blend`）补回来。
5. **提示词结构**：`主体 + 动作 + 场景 + 镜头运动 + 光线 + 风格 (+ 音频)`。一个镜头只写一个主要动作；镜头运动用固定词汇（推、拉、摇、移、跟、升、降、环绕）；一律写上"画面内无文字、无字幕、无水印"，字幕在后期加。
6. **多镜头生成用在需要连贯的地方**：群像、剧情这类需要同一空间连续动作的段落，用 Seedance 或可灵的单次多镜头生成（提示词里写 `Shot 1 / Shot 2`）；其余镜头单独生成，便于逐个重做。
7. **原生音频只留环境音**：人声旁白统一用 TTS，音乐单独生成，三轨在合成时混音。视频模型自带的人声音色在镜头之间不一致，时长也不可控，合成时静音或压低它。
8. **best-of-N**：开头钩子镜头和副歌高潮镜头生成 2–3 个候选，由质检模型选；普通镜头只生成 1 个，不合格再重做。
9. **先草稿后成片**：草稿阶段用 Seedance mini 或可灵 Turbo 720p，确认后只对选中的镜头出 1080p。注意 Seedance 2.0 最高只到 720p，需要 1080p 时用超分，或者把这个镜头换给可灵。
10. **物理内容分工**：AI 视频只拍"现象"（彩虹、单摆、雷电、潮汐）；公式、受力图、坐标轴一律用 Manim 精确绘制后叠加。视频模型生成的文字和物理过程都不可靠。
11. **一镜到底（长镜头链）**：沿镜头路径先出 3–4 张关键帧（比如城楼航拍 → 下降到街道 → 推到酒楼门口），保持同一场景、同一光线；相邻两张用首尾帧模式生成中间的运动，再把片段首尾相接。每段的尾帧就是下一段的首帧，所以看不出接缝，30 秒一般是 2–3 段。可灵支持首尾帧；Seedance 2.0 能不能指定尾帧，要在 Phase 0 确认，不行就用它的视频参考或延长功能。
12. **文字不交给视频模型**：片名书法字、印章、金句都在后期叠加。可以用 GPT Image 2 或 Seedream 生成透明底的书法字（这两个模型写中文好），也可以用有商用授权的书法字体，再用 FFmpeg 加淡入、描边、做旧效果。画面里的牌匾和招牌在关键帧阶段就用图像编辑改成正确的字（比如"醉仙楼"），图生视频基本能保住；质检时用 OCR 查乱码。
13. **调色与质感**：每个风格预设带一套 LUT、胶片颗粒和暗角，横屏还可以加遮幅；需要更清晰时，再对选中的片段做超分。样片的"电影感"很大一部分来自这一步，几乎不花钱。
14. **巨物美学**：构图是"极小的人物 + 巨大的植物、月亮、鱼或建筑"，低机位、浅景深。运镜用揭示式：先拍人物近景，再缓慢拉远露出巨物，或者反过来。比例要在出图阶段就做对，视频模型很难自己改比例。
15. **名画活化**：取公版名画的高清图 → 用图像模型扩图到目标画幅 → 图生视频，提示词写"保持原画笔触和色彩，只做细微运动"（星光闪烁、水波、衣袂、人物的小幅动作）。长卷（如《清明上河图》）按顺序截 4–6 个窗口当关键帧，用首尾帧串起来，就是一条"长卷一镜到底"。

### 4.5 音频

- **旁白**：豆包语音合成 2.0 有单独的"情感预测版"接口（[火山引擎文档](https://www.volcengine.com/docs/6561)）；MiniMax Speech 2.8 支持声音标签，10 秒音频即可克隆，在百炼上 ¥2/万字符（[阿里云百炼](https://help.aliyun.com/zh/model-studio/speech-2-8-turbo)）。300 字旁白的成本不到 ¥0.1，可以两家都试，按古诗朗诵的听感选。
  - 古诗朗诵：语速 0.85–0.95，句间停顿 0.6–0.8 秒，一句一段合成再拼接，停顿完全可控。
  - 字幕时间轴：优先用 TTS 返回的时间戳；拿不到就用 FunASR 或 WhisperX 做强制对齐。
- **歌曲**：Suno v5.5（3 月 26 日发布，新增 Voices 和自定义模型，[官方博客](https://about.suno.com/blog/v5-5)）中文人声质量最好，但**没有官方 API**，第三方封装有封号和合规风险。建议做成半自动步骤：系统生成歌词和风格提示词 → 你在 Suno 或海绵音乐里生成 → 把文件放进项目的 `music/` 目录 → 系统接着往下跑。全自动路径用 MiniMax Music 3.0（第三方托管约 $0.002/秒，[EmpirioLabs](https://catalog.empiriolabs.ai/models/minimax-music-3)），但官方 API 的开放状态目前说法矛盾，需要核实。
  - 红歌、流行歌大多还在版权期，**不要 AI 翻唱**。"高亢颂歌""男女高音"可以用原创歌词加风格描述来生成。
  - **歌曲具象化**用的是现成的歌：制作时用歌曲音频确定节拍和歌词时间轴；成片导出两版（带歌的预览版、不带歌的发布版），最稳妥的做法是发布时在抖音里从曲库选同一首歌并对齐起点。曲库授权只在抖音站内有效，发到别的平台要换音乐；企业号能用的曲库范围更小。
  - 歌词字幕：先用 Demucs 分离人声，再用 FunASR 对齐。
- **混音**：旁白 −16 LUFS 左右，BGM 在旁白出现时自动压低 10–12 dB（FFmpeg `sidechaincompress`），整体用 `loudnorm` 标准化。

```
    topic/            # calendar.py, corpus.py, scoring.py
    writer/           # script.py, storyboard.py（LLM 提示链 + JSON Schema）
    providers/        # base.py：submit / poll / estimate_cost 统一接口
                      # seedance.py, kling.py, minimax_h3.py, seedream.py,
                      # tts_doubao.py, tts_minimax.py, music_minimax.py, avatar_kling.py
    qc/               # vlm_judge.py, ocr_check.py, face_sim.py
    compose/          # ffmpeg.py, subtitles_ass.py, mixer.py, jianying.py, manim_overlay.py

```

| 阶段                                                                                                | 时长   | 内容                                                                                                                                                                                                                 | 验收标准                                                                   |
| --------------------------------------------------------------------------------------------------- | ------ | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------- |
| **Phase 0 模型实测**（工具已就绪：[apps/ai-video](../apps/ai-video/README.md) 的 `ai-video bench`） | 3–5 天 | 每个方向选 1 个题，同一份分镜分别跑 Seedance 2.0 / 可灵 3.0 / H3；图像对比 Seedream 和 GPT Image 2；TTS 对比豆包和 MiniMax；LLM 盲评；**专门测 Seedance 对国风人物的拒绝率**；办好火山方舟企业认证和可灵开放平台账号 | 产出一张路由表（方向 × 镜头类型 → 模型）和实测单价表                       |

| **Phase 2 可控性**                                                                                  | 1–2 周 | 分镜联系表（自动生成的 HTML，显示每镜首帧、提示词、状态和重做按钮）；角色库和风格库（含调色 LUT 和颗粒）；文字层（书法标题、印章、金句）；best-of-N 与视觉质检；导出剪映草稿（pyJianYingDraft）                      | 任意单个镜头可以重做而不影响其他镜头；质检能拦下明显崩坏的镜头             |
| **Phase 3 音乐与数字人**                                                                            | 1–2 周 | T2：原创歌曲或歌曲具象化 → 节拍检测 → 卡点剪辑；长镜头链（一镜到底）；T3：分段对口型 + B-roll；歌词字幕对齐                                                                                                          | 美景、特效、长征、数字人唱歌各出 1 条成片，外加一条 30 秒一镜到底          |
| **Phase 4 选题引擎、物理与名画**                                                                    | 1 周   | 节气和纪念日日历、古诗文库和名画库入库、打分去重、系列管理；物理模板接入 Manim 公式叠加、科幻叙事模式和事实核查；名画活化模板                                                                                        | 每周一自动推送 10 个带分数的选题                                           |
| **Phase 5 群像与发布**                                                                              | 持续   | T4 多镜头叙事；发布清单（标题、话题、封面、AI 声明）；手工记录播放和完播数据，回流到选题打分                                                                                                                         | 群像成片可用；数据能影响下一轮选题                                         |

发布环节建议保持人工点"发布"：抖音开放平台的视频发布接口需要企业资质，用浏览器脚本自动上传有封号风险，而且合规上也需要人最后把关。系统只要准备好 mp4、标题、话题、封面和 AI 声明。

## 7. 成本与耗时估算（60 秒成片，估算值）

| 项目        | T1 旁白型                                | T3 数字人唱歌                                       |
| ----------- | ---------------------------------------- | --------------------------------------------------- |
| 视频生成    | 约 85 秒（含 30% 重做）× ¥0.5–1 = ¥43–85 | 对口型 60 秒 × ¥0.12–1 + B-roll 20 秒 × ¥1 = ¥27–80 |
| 关键帧      | 24 张 × ¥0.3–0.65 = ¥7–16                | 定妆照 + B-roll 首帧约 ¥5                           |
| 旁白 / 歌曲 | < ¥0.1                                   | MiniMax 约 ¥1，或 Suno 订阅                         |
| LLM 与质检  | < ¥2                                     | < ¥2                                                |
| **合计**    | **约 ¥50–100**                           | **约 ¥35–90**                                       |

耗时取决于排队情况，镜头并发提交的话，一般几十分钟能出一条（Phase 0 实测后修正）。

要做到你收藏里那种爆款品质，每个镜头一般要出 3–5 个候选再挑，视频成本大约是上表的 2–3 倍。以 30 秒一镜到底为例：2–3 段 × 15 秒 × 3 个候选 × ¥1/秒，约 ¥90–135。
