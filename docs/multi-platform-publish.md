# 多平台发布（浏览器扩展）

在扩展版编辑器里点「发布」，把当前文章填进各平台的编辑器并保存为草稿。**不会自动点击发布**，每个平台都需要你检查排版后手动发布。

网页版（非扩展）不受影响，仍然使用原来依赖 [COSE](https://github.com/doocs/cose) 扩展的「发布」对话框。

## 使用

1. 构建并加载扩展：
   ```bash
   pnpm web ext:zip        # 或开发模式：pnpm web ext:dev
   ```
   Chrome / Edge 打开「扩展程序 → 开发者模式 → 加载已解压的扩展程序」，选择 `apps/web/.output/chrome-mv3`。
2. 打开编辑器（扩展选项页或侧边栏），点顶部「发布」，或「文件 → 多平台发布」（侧边栏较窄时只有菜单入口）。
3. 首次使用点「授权」，在浏览器弹窗里确认。之后对话框会检测各平台的登录状态；未登录的点「去登录」。
4. 勾选平台，点「同步到草稿」。对话框关闭，打开「发布中心」显示进度；扩展会依次打开并切换到各平台的标签页（归在一个标签组里），填完后回到编辑器。
5. 在各平台标签页检查排版，手动发布，再回到发布中心把这个平台「标记为已发布」（可以附上文章链接）。

每个平台填完后，扩展会读回编辑器里的内容长度来判断结果，发布中心里显示为：

- **草稿已存**：标题和正文都在，草稿已保存（或平台会自动保存）。
- **需检查**：标题被截断、标题没填进去、正文明显不完整、需要手动保存草稿，或文章里有这个平台显示不了的内嵌 / 本地图片。
- **需要登录**：页面跳到了登录页，或平台页面显示未登录。
- **失败**：没找到编辑器（多半是平台改版）或超时。平台详情里的「诊断信息」是给排查用的英文说明，里面带了页面路径、标题和页面上编辑器元素的数量（不含网址参数，不会泄露登录 token），反馈问题时截图这部分即可。
- **已发布**：你在发布中心里标记过。
- **未同步**：这篇文章还没同步到这个平台。

## 超长文章自动拆分

平台对正文长度有上限时（知乎按 4 万字算；头条按 2 万字算，头条没公布上限，36682 字的文章存不上、拆成一半就能存；和发布中心里的字数同一口径），超出的文章同步到该平台时会自动拆成上、下两篇，各存一份草稿；两篇还放不下就拆成上、中、下，再长就按「1/4」这样编号。其他平台照常收到整篇。

- 只在标题处拆，优先二级标题，在二级标题里选让各篇长度最接近的位置；代码块、表格都在标题之间，不会被拆开。
- 标题后面加「（上）」「（下）」，超出平台标题长度时截短原标题、保留后缀。
- 上篇末尾加「（未完，接下篇《…》）」，下篇开头加「（接上篇《…》）」。
- 脚注和链接定义跟着用到它们的那一篇。
- 发布中心里这个平台显示「分 2 篇」，详情里列出每一篇的状态，各有「打开草稿」。发布时按顺序发。
- 文章里没有标题可拆、或单独一节就超过上限时不拆，这时知乎会报「超出字数上限」，头条存不上草稿（code 5009）。

## 发布中心

「文件 → 发布中心」，或多平台发布对话框底部的「发布中心」按钮。每篇文章单独记录，可以在顶部切换。

- **版本**：每次同步时记下文章内容的指纹，第一次出现的内容依次编号 v1、v2……。之后改了文章，已经同步过的平台会标出「草稿是 v2」或「发布后改过」，顶部提示哪些平台是旧版本。
- **重新同步**：在平台行或详情里点「重新同步」「重试」，或在提示里一次重新同步所有旧草稿。标题和摘要沿用上次同步时手动填的值；上次用的是默认值时，按改过的文章重新生成。目前每次重新同步都会在平台上**新建**一份草稿，旧草稿要自己删除。
- **打开草稿**：切回同步时打开的标签页。标签页关了、或浏览器重启过（标签页编号会被复用，扩展会先核对网址），就只能去平台的草稿箱里找。
- **标记已发布**：记下发布的是哪个版本和文章链接（只接受 http / https 链接），可以取消标记。已发布的文章之后改了，需要到平台的编辑页手动更新。
- **只看当前文章**：只能同步编辑器里正在编辑的文章；查看其他文章时，先点「在编辑器中打开」。
- 记录保存在本机（`MD__publish_records`），不参与云同步：标签页和草稿都只属于这个浏览器。

## 图片与公式

- **发布前先传图床**（`services/publish/hosting.ts`）：在「图床」设置里选了图床（腾讯云 COS、阿里云 OSS、七牛、S3 等；不包括「默认」和「公众号图床」）时，同步开始前，扩展页先把文章里所有内嵌（base64）的位图上传到这个图床，所有平台拿到的都是图片链接。
  - **同一张图只传一次**：一次同步里，同一张图只上传一次；和编辑器粘贴上传共用「图床 + 图片内容哈希 → 链接」的缓存（`uploaded_image_map`），以后重新同步也不再传。
  - **格式**：WebP、BMP 先在扩展页转成 PNG，JPEG 不到 PNG 一半大时用 JPEG（照片），因为不是每个平台都收 WebP。
  - **单独生成的图片**：百家号、B 站要的表格图片、公式图片，在扩展页画好后同样上传。
  - **进度和失败**：发布中心顶部实时显示「正在把图片上传到图床 12 / 20」和进度条，传完后显示有几张在图床。传不上去的图保留内嵌，照旧同步，发布中心用橙色提示写明有几张没传上和原因。这条状态只保留在内存里，下次同步时清掉。
  - **转存到平台自己的图床**：公众号、头条、百家号、B 站只显示自家图床的图，同步时在平台页面里按链接把图读回来，再转存到自己的图床。所以图床必须允许跨域读取，比如腾讯云 COS 的「安全管理 → 跨域访问 CORS 设置」：来源 `*`，方法 GET、PUT、POST、HEAD，Allow-Headers `*`。扩展页上传本身也要靠这条规则。
  - **不选图床**：没选图床（或选的是「默认」）时，和以前一样保留内嵌图片。
- **图片**：公众号会在填写前把内嵌（base64）图片和不在微信 CDN（`qpic.cn`、`qlogo.cn`）上的链接图片上传到你的图片素材库，再换成素材库链接（WebP 会先转成 PNG，公众号不收 WebP）；没传成功的会在结果里提示。其他平台只能接收公网链接：文章里有内嵌或本地路径的图片时，对话框会提示，先用图床上传再同步。公网图片由平台自行转存或直接引用。百家号例外：编辑器只显示百度自家图床上的图，外链图放进去是空白，所以同步前会把内嵌图片和外链图片都传到百家号素材库（`uploadHtmlImages`；外链图在百家号页面里下载，图床要允许跨域读取，比如腾讯云 COS 的「跨域访问 CORS」规则）；本地路径（`images/x.png`）的图读不到，结果里会写明是哪一张。用「导入 Markdown」导入带本地图片的文章时，md 在你选的文件夹（含子文件夹）里按文件名找图并上传到图床；几个文件同名时，取文件夹路径和文章里写的路径最接近的那个（比如 `images/x.png` 优先于 `images/raw/x.png`）。不在所选文件夹里的图找不到，会保留成坏链接，所以只发公众号的二维码要直接内嵌在文章里。
- **只发公众号的图**：公众号二维码这类站外引流图，别的平台会限流或删文，所以只发公众号。带 `data-publish-only="wechat"` 的图（hollis23 的 `watermark.py` 内嵌文件名含 `_wxonly` 的图时会加上），或地址里含 `_wxonly` 的图，同步到其他平台（包括百家号、B 站）时会被去掉，前后文字保留。
- **B 站的图片和表格**：B 站编辑器会自己把粘贴进来的内嵌图片传到 B 站图床，但一次全部并发上传，常有几张失败。同步时先把 WebP 转成 PNG，把图床上的链接图片读回成内嵌图片（编辑器只上传内嵌图片；读不到的计为失败，草稿同样不存）再粘贴，等第一轮传完，再用每张图自己的「重新上传」逐张重传失败的（最多四轮，每轮前多等几秒）；还失败的，发布中心会列出 B 站给的原因。这时草稿存不了：没传上去的图在编辑器里还是 base64，保存时会原样发给 B 站，B 站拒收（页面底部显示「保存失败，请尝试手动保存」，自动保存也一样），所以扩展不点保存，发布中心提示到编辑器里点这几张图的「重新上传」，传好后再保存草稿。编辑器没有表格（粘贴进去会挤成一段文字），所以同步到 B 站前，扩展页会用 `html-to-image` 把每张表格画成 PNG（格子里的公式先用 MathJax 画好），和其他图片一起上传。
- **知乎为什么不贴 Markdown**：2026 年起，知乎把纯文本像 Markdown 或 HTML 的粘贴先发给服务端判断（`/editor/paste/type`），内容不进编辑器，只弹出「识别到特殊格式……确认并解析」；点了以后整篇发到 `/editor/paste/parse` 解析，5 秒没解析完就放弃（「似乎出了点问题，请重试」），编辑器一直是空的。内嵌了图片的文章动辄几百 KB，基本解析不完。纯文本部分为空的粘贴会跳过这一步，由编辑器在页面里导入 HTML，所以现在知乎直接贴 HTML。编辑器里已有内容时先选中，让粘贴替换掉，不直接清空 DOM（知乎是 Draft.js，手动清空会让编辑器失灵）。
- **公式**：Markdown 平台保留 `$…$` 源码，由平台渲染；公众号用 MathJax 渲染的 SVG；百家号的 UEditor 会去掉 SVG（公式处只剩空白），并把每张图片都变成单独一块带图注的图（行内图片会把句子和列表项从中间拆开），所以（`plainFormulas`）独占一行的公式由扩展页画成 PNG（3 倍分辨率，相同公式只画一次），再由 agent 和其他内嵌图片一起传到素材库；行内公式转成纯文字（`services/publish/tex-text.ts`：`3.8 × 10²⁵`、`2/3 · 4d`、`N*(C) = AC^α`，数字上下标用 Unicode 上下标，其余写成 `^(…)` / `_(…)`，不用 `<sup>`，因为编辑器去掉它时 10²² 会变成 1022；公式内部用不换行空格），认不出的命令退回 `$…$` 源码；头条退回 TeX 文本。知乎换成它自己的公式写法 `<img eeimg="1|2" alt="TeX">`（2 是独占一行的公式），粘贴时由知乎导入成公式。B 站换成编辑器自带的公式节点（由 B 站的 TeX 服务渲染，独占一行的公式居中并用 `\displaystyle`）：无样式 HTML 里每个公式都带着 TeX（`data-tex`），粘贴时先换成占位文字，粘贴完再换成公式节点，因为粘贴内容里只要有一个 B 站公式图片，编辑器就不处理其余图片的上传。扩展页面的 CSP 不允许加载远程脚本，所以构建时会把 MathJax 打包进扩展（`static/libs/mathjax/tex-svg.js`，与 uTools 版同一机制），否则扩展里的公式一直显示「…」。

## 公众号的编辑器地址

新建文章的地址有两种（`type=10` 和 `type=77`）。先打开 `type=10`；如果 20 秒内没出现编辑器，再试 `type=77`；两种都不行才报「没找到编辑器」。登录状态只在编辑器没出现时才判断，而且只看页面上可见的文字：编辑器页面里藏着「扫码确认」之类的隐藏对话框，不能据此判断为未登录。

## 权限

- 平台域名、`scripting`、`cookies`、`tabGroups`（仅 Chrome / Edge）都是**可选权限**，第一次使用时才申请，安装或升级扩展不会新增权限提示。
- 只有扩展自己的页面能发起同步，普通网页无法调用。
- `cookies` 只用来读取 CSDN 的登录 cookie，判断是否已登录。

一次同步的流程：对话框 → `buildAgentArticle` → 选了图床时 `createImageHosting` 把内嵌图片换成图床链接 → `runPublish` → 每个平台：打开标签页 → 等待加载 → 检查是否跳到登录页 → 注入 `publish-agent.js` → 执行步骤（可能先 `prepare` 再跳转到 `fill`）→ 读回结果 → 写进这篇文章的发布记录。

## 新增或修改平台

1. `publish-agent/protocol.ts` 的 `PUBLISH_PLATFORM_IDS` 加上平台 id。
2. 新建 `publish-agent/platforms/<id>.ts`，实现 `fill`（需要先建草稿或拿 token 时再加 `prepare`，返回 `navigate(url, 'fill')`），并在 `publish-agent/index.ts` 注册。
3. `services/publish/platforms.ts` 加一项：`startUrl`、`hostPermissions`（要覆盖用到的所有 URL）、`loginUrlPattern`、`format`、`detectLogin` 等。
4. 四个语言的 `i18n/messages/*/publish.ts` 里加 `publish.platforms.<id>`。
5. 测试：`platforms.test.ts` 会检查权限是否覆盖所有 URL；在 `publish-agent/platforms/platforms.test.ts` 为新平台加一个页面结构的测试。
6. `pnpm web test`，然后重新构建扩展，在扩展管理页点「重新加载」。

平台改版导致选择器失效时，先看失败信息里的英文说明，再对照 [doocs/cose](https://github.com/doocs/cose) 和 [MultiPost-Extension](https://github.com/leaperone/MultiPost-Extension) 里同一平台的最新实现。两者都是 Apache-2.0，本功能参考了它们的做法，见 `apps/web/src/publish-agent/THIRD_PARTY_NOTICES.md`。

## 已知限制

- 只在 Chromium（Chrome / Edge）上验证过；Firefox 构建能生成，但没有测试。
- 各平台的页面结构和接口参照 COSE / MultiPost 的实现，本仓库的测试只用模拟页面验证了流程；平台改版后需要跟着更新。
- 不会自动点击「发布」，也无法自动知道你是否已发布，需要在发布中心里手动标记。
- 重新同步总是新建草稿，还不能覆盖原来那份。
